Integraciones API entre ERP y sistemas de negocio

La integración buena no presume de conectores: presume de contratos, reintentos y datos que se pueden explicar.

En proyectos reales el dolor no suele ser “llamar a una API”. Es decidir qué sistema es maestro, qué pasa cuando falla una sincronización y cómo se audita sin filtrar información sensible.

Contratos antes que código

  • Definir campos, ownership y frecuencia de sync.
  • Versionar payloads cuando el consumidor no puede actualizar al mismo ritmo.
  • Documentar errores esperables (timeouts, duplicados, permisos).

Idempotencia y reintentos

Las redes fallan. Un conector Python entre Odoo y otro servicio debe poder reintentar sin crear duplicados. Eso implica claves de idempotencia, estados claros y logs útiles para soporte.

Menos magia, más operación

Prefiero pipelines aburridos: colas o jobs programados, alertas simples y dashboards mínimos. Si solo funciona “cuando yo estoy online”, no es una integración: es un riesgo.

Privacidad por diseño

En entornos con datos de clientes o de planta, minimizo campos transferidos, separo entornos y evito logs con información personal. El detalle del negocio se resuelve; los datos personales no viajan de más.
